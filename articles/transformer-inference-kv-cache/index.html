How Transformer LLMs Generate Text: Prefill, Decode, and the KV Cache

How does a trained Transformer generate text one token at a time—and how does the KV cache keep it from recomputing the same prefix at every step?

August 2026 18 min read

This article starts with a trained model. For embeddings, Transformer blocks, attention, and training, read Transformer LLMs for Beginners.

1. From Prefill to Decode

Once training is complete, the model's projection and MLP weights stay fixed. Inference then proceeds in two distinct stages: Prefill and Decode.

Prefill: Process the Known Prompt in Parallel

Every prompt token is known when the request begins, so each Transformer layer can process all prompt positions in parallel.

Decode: Reuse Keys and Values

Decode produces one new token at a time while reusing the keys and values computed for earlier positions.

How Much Computation Does the KV Cache Save?

The most direct saving comes from avoiding repeated K/V projections for historical tokens at every decode step.

What Does Caching Cost?

The trade-off is accelerator memory: every layer stores a key and a value for every cached token.

Can We Use Fewer Cached Heads?

MHA, GQA, and MQA differ in how query heads share K/V heads, changing both cache size and K/V-projection cost.

How Providers Price Cached Tokens

Provider billing is a product policy layered on top of the underlying caching mechanism and can change over time.

2. Prompt Caching Across Requests

A normal KV cache reuses work within one generation. Prompt caching extends prefix reuse across requests and conversation turns.

OpenAI Prompt Caching Requirements

OpenAI-specific behavior belongs in a dated provider note rather than in the model-independent explanation.

How to Improve the Cached-Token Hit Rate

Place the most stable, broadly reusable content first and the most dynamic, request-specific content last.

Common Cache-Breaking Patterns
